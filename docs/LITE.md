# WeKnora Lite 与标准版区别

Lite 面向希望快速在本地使用、部署尽量简单的场景；标准版面向多空间协作与完整企业能力。主要差异如下。


| 维度        | Lite                                            | 标准版                               |
| --------- | ----------------------------------------------- | --------------------------------- |
| **共享空间**  | 不提供共享空间（成员邀请、跨成员共享知识库与智能体等）                     | 提供共享空间及空间隔离检索等协作能力                |
| **空间与账号** | 单空间；开箱即用，**无需注册**                               | 多空间；通常需要注册、登录与组织管理                |
| **文档解析**  | 内置仅 **Simple** 类型解析引擎；可通过 **Cloud** 等方式接入其他解析能力 | 可配置多种解析引擎（含高精度等），与完整文档处理链路集成      |
| **部署形态**  | **单应用进程**（外部只需一个 PostgreSQL，消息队列用内存实现）               | 典型为 Docker Compose 等多服务部署，依赖与组件更多 |
| **数据归属**  | 数据**完全在本地**存储与处理                                | 私有化部署时数据也可在本地；具体取决于你的部署方式         |
| **网络暴露**  | **默认仅本机访问**；可按需配置，**选择是否放行到公网**                 | 按部署与安全策略自行绑定地址与网关                 |


## 数据库：只支持 PostgreSQL

WeKnora 已**全面退场 SQLite**，只跑 PostgreSQL（pgvector）。这一条对 Lite 同样生效：

- `DB_DRIVER` 只接受 `postgres`，填别的值启动直接失败。
- 检索走 `RETRIEVE_DRIVER=postgres`（复用应用自己的 pgvector 连接）。
- 没有 `DB_PATH` 这个变量 —— 它是 SQLite 时代的产物。

所以 Lite 的「零外部依赖」不再成立：**至少要有一个 PostgreSQL 实例**（本机装一个，或指向已有的）。

## 内存消息队列

Lite 不需要 Redis：`STREAM_MANAGER_TYPE=memory` 用进程内队列代替。

若你不需要多团队协作、复杂解析流水线与多服务架构，Lite 更适合个人或小团队在本机快速试用；需要共享空间、多空间与完整解析引擎矩阵时，请使用标准版。
